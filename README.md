# Тестирование Restful Booker API

## Описание

В данном проекте представлены результаты функционального и негативного тестирования API сервиса **Restful Booker**.

Цель тестирования — проверить корректность работы основных API-операций, валидацию входных данных, авторизацию, обработку ошибок и корректность изменения данных.

## Область тестирования

Были протестированы следующие эндпоинты:

| Метод  | Эндпоинт        | Назначение                                 |
| ------ | --------------- | ------------------------------------------ |
| POST   | `/auth`         | Авторизация и получение токена             |
| GET    | `/ping`         | Проверка доступности API                   |
| POST   | `/booking`      | Создание бронирования                      |
| GET    | `/booking`      | Получение списка бронирований и фильтрация |
| GET    | `/booking/{id}` | Получение конкретного бронирования         |
| PUT    | `/booking/{id}` | Полное обновление бронирования             |
| PATCH  | `/booking/{id}` | Частичное обновление бронирования          |
| DELETE | `/booking/{id}` | Удаление бронирования                      |

## Что проверялось

В рамках тестирования были проверены:

* позитивные и негативные сценарии;
* обязательные поля;
* типы входных данных;
* форматы дат;
* корректность диапазона дат;
* фильтрация бронирований;
* обработка `booking ID`;
* полное и частичное обновление данных;
* авторизация и проверка токена;
* HTTP-статусы;
* корректность данных в ответах;
* обработка некорректных запросов;
* граничные и невалидные значения.

## Инструменты

* **Postman** — отправка запросов и проверка ответов API;
* **Microsoft Excel** — документирование тест-кейсов и баг-репортов;
* **Restful Booker API** — тестируемое приложение.

## Результаты тестирования

В ходе тестирования были обнаружены проблемы, связанные с:

* серверной валидацией входных данных;
* обработкой некорректных типов данных;
* валидацией дат;
* обработкой некорректных `booking ID`;
* автоматическим приведением типов данных;
* проверкой диапазона дат;
* работой фильтров;
* обработкой ошибок;
* выполнением операций удаления с некорректными идентификаторами.

Особое внимание было уделено негативным сценариям, позволяющим выявить поведение API при передаче некорректных или неожиданных данных.

## Найденные дефекты

По результатам тестирования было оформлено **27 баг-репортов**.

Для каждого дефекта указаны:

* краткое описание проблемы;
* эндпоинт;
* Severity;
* Priority;
* предусловия;
* шаги воспроизведения;
* ожидаемый результат;
* фактический результат;
* текущий статус.

Наиболее значимые проблемы связаны с валидацией входных данных и обработкой некорректных `booking ID`.

В частности, были обнаружены сценарии, при которых некорректный идентификатор может привести к изменению или удалению существующего бронирования.

## Артефакты

В проект входят:

* `YASP_Test.xlsx` — набор тест-кейсов с ожидаемыми и фактическими результатами;
* `BugReports.xlsx` — найденные дефекты с шагами воспроизведения;
* `Restful Booker.postman_collection.json` — коллекция запросов Postman;
* `README.md` — описание проведённого тестирования.

## Примечания

Результаты отражают поведение API, полученное непосредственно в процессе тестирования.

Ожидаемые результаты определялись на основании назначения эндпоинта, API-документации, HTTP-стандартов и требований к валидации входных данных.

Не каждый неожиданный HTTP-статус был автоматически классифицирован как дефект. Например, `405 Method Not Allowed` не считался багом, если API корректно отклонял некорректный запрос.

## Итог

В рамках работы было проведено функциональное и негативное тестирование основных операций Restful Booker API.

Тестирование позволило проверить жизненный цикл бронирования — от создания и получения до изменения и удаления, а также авторизацию, валидацию входных данных и обработку ошибок.

По результатам тестирования было подготовлено **27 баг-репортов**, содержащих воспроизводимые сценарии обнаруженных проблем.
